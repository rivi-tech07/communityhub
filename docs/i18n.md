# Internationalisation workflow

CommunityHub keeps user-facing mobile auth, onboarding, home-shell, and profile
strings in JSON catalogs under `packages/shared/i18n`. The initial locales are
`en-GB` and Gujarati (`gu`). The admin dashboard remains English-only for now.

## Adding a locale

1. Copy `packages/shared/i18n/en-GB.json` to a new locale filename using the
   BCP-47 language tag used by the profile `preferred_language` value.
2. Translate every key without adding or removing keys. Keep interpolation
   tokens such as `{{seconds}}` unchanged.
3. Add the catalog import and locale entry in
   `packages/shared/i18n/index.ts`.
4. Run `pnpm test -- tests/i18n.test.ts` and the formatter. The test fails if
   the catalogs drift or a migrated screen reintroduces its extracted copy.
5. Wire the locale into profile data only after the catalog is complete. Users
   initially follow `profiles.preferred_language`; the mobile shell's language
   control is an explicit temporary override for the current session.

Do not put secrets, provider messages, or server-only operational text in these
catalogs. Add new UI copy through the catalogs before using it in a migrated
screen.
