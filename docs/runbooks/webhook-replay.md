# Webhook replay runbook

| Field                           | Procedure                                                                                                                                                                                                                                                                                                                              |
| ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Symptom                         | A row in `payment_events` remains `failed`, or a provider reports a delivery failure.                                                                                                                                                                                                                                                  |
| Impact                          | `payment_transactions`, `orders`, or `promotions` may not reflect a verified provider event.                                                                                                                                                                                                                                           |
| Detection                       | Query `payment_events.status`, `last_error`, `attempts`, `provider`, and `provider_event_id`; correlate with provider delivery logs.                                                                                                                                                                                                   |
| Immediate mitigation            | Verify the signature was accepted originally and confirm the provider event is genuine. Do not replay `processed`, `ignored`, or unknown payloads. **requires provider console**                                                                                                                                                       |
| Root cause investigation        | Inspect `payment_events.payload`, `event_type`, matching `payment_transactions.provider_payment_id`/`provider_order_id`, and application logs. Preserve the original `provider_event_id`.                                                                                                                                              |
| Recovery steps (exact commands) | `curl -sS "$SUPABASE_URL/rest/v1/payment_events?status=eq.failed&id=eq.$EVENT_ROW_ID&select=provider,provider_event_id,event_type,payload" -H "apikey: $SUPABASE_SERVICE_ROLE_KEY" -H "Authorization: Bearer $SUPABASE_SERVICE_ROLE_KEY" > /tmp/payment-event.json`; build the RPC body without changing the stored payload: `jq '.[0] | {p_provider:.provider,p_provider_event_id:.provider_event_id,p_event_type:(.event_type // ""),p_provider_payment_id:(.payload.data.object.payment_intent // .payload.data.object.id // .payload.payload.payment.entity.id // .payload.payload.refund.entity.id // null),p_provider_order_id:(.payload.data.object.order_id // .payload.payload.payment.entity.order_id // .payload.payload.refund.entity.order_id // null),p_payload:.payload}' /tmp/payment-event.json > /tmp/payment-event-rpc.json`; then call the service-only RPC: `curl -sS "$SUPABASE_URL/rest/v1/rpc/process_payment_event" -H "apikey: $SUPABASE_SERVICE_ROLE_KEY" -H "Authorization: Bearer $SUPABASE_SERVICE_ROLE_KEY" -H 'content-type: application/json' -d @/tmp/payment-event-rpc.json`. Never alter the event ID or payload. |
| Post-incident actions           | Confirm the row is `processed` or intentionally `ignored`, verify the transaction/order state, and compare provider delivery status. Repeated calls are protected by `(provider, provider_event_id)` and processed rows are no-ops.                                                                                                    |
| Owner                           | Payments on-call.                                                                                                                                                                                                                                                                                                                      |

The webhook route is `apps/web/app/api/payments/webhooks/[provider]/route.ts`; it verifies signatures before database writes. The replay RPC is service-role-only. Provider delivery history **requires provider console** access.
