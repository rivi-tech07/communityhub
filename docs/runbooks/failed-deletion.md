# Failed account deletion runbook

| Field                           | Procedure                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Symptom                         | A `deletion_requests` row is `failed`, or remains `processing` after the worker stopped.                                                                                                                                                                                                                                                                                                                                                                                 |
| Impact                          | The account may remain blocked while profile/storage data is only partially anonymized or removed.                                                                                                                                                                                                                                                                                                                                                                       |
| Detection                       | Query `deletion_requests.status`, `attempts`, `last_error`, and `requested_at` with the service-role key.                                                                                                                                                                                                                                                                                                                                                                |
| Immediate mitigation            | Keep sign-in disabled; do not manually delete rows or the Auth user out of order. Preserve the request ID and error.                                                                                                                                                                                                                                                                                                                                                     |
| Root cause investigation        | Inspect worker output, storage bucket errors, profile/CV/business-media permissions, and whether `moderation_audit_log` already contains `account_deletion` for `deletion_request:<id>`.                                                                                                                                                                                                                                                                                 |
| Recovery steps (exact commands) | `curl -sS "$SUPABASE_URL/rest/v1/deletion_requests?id=eq.$REQUEST_ID&select=id,user_id,status,attempts,last_error" -H "apikey: $SUPABASE_SERVICE_ROLE_KEY" -H "Authorization: Bearer $SUPABASE_SERVICE_ROLE_KEY"`; retry one request with `SUPABASE_URL="$SUPABASE_URL" SUPABASE_SERVICE_ROLE_KEY="$SUPABASE_SERVICE_ROLE_KEY" pnpm process:deletions -- "$REQUEST_ID"`. For a queue retry, run `SUPABASE_URL=... SUPABASE_SERVICE_ROLE_KEY=... pnpm process:deletions`. |
| Post-incident actions           | Confirm status `completed`, Auth identity removal, tombstone profile, private storage deletion, and one audit row. If the failure is systemic, leave rows retryable and page the privacy owner; do not bypass the worker.                                                                                                                                                                                                                                                |
| Owner                           | Privacy/data operations on-call.                                                                                                                                                                                                                                                                                                                                                                                                                                         |

The worker is `scripts/process-deletions.mjs`. It is idempotent for completed requests and uses `SUPABASE_SERVICE_ROLE_KEY` only on the server/worker.
