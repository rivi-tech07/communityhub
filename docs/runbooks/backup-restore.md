# Backup and restore runbook

| Field                           | Procedure                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Symptom                         | Production data is corrupted, unavailable, or requires point-in-time recovery.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Impact                          | Users may lose access or see incorrect profile, order, payment, or community data.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Detection                       | Supabase availability alerts, application 5xx/error rate, RLS failures, or verified data-integrity checks.                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Immediate mitigation            | Freeze destructive maintenance and deployments; preserve the incident timestamp and choose a scratch project. Do not restore over production first.                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Root cause investigation        | Establish the last known-good time, affected tables, migration versions, storage objects, Auth identities, and provider settlement impact.                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Recovery steps (exact commands) | In Supabase Dashboard, choose the production project’s PITR/backup and restore it to a separate scratch project: **requires provider console**. Then run `supabase link --project-ref "$SCRATCH_PROJECT_REF"`, `supabase db push --dry-run`, and `supabase db dump --linked --schema public -f /tmp/communityhub-scratch.sql`. Run the application’s read-only checks against the scratch URL; never point production clients at scratch. If an approved cutover is required, create a change window, verify migrations/RLS/payment state, update server secrets, and redeploy. |
| Post-incident actions           | Record restore point, RTO/RPO achieved, validation results, data loss, and provider reconciliation. Rotate exposed credentials and unlink scratch access when finished.                                                                                                                                                                                                                                                                                                                                                                                                         |
| Owner                           | Platform/SRE on-call; data owner approves cutover.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |

## Quarterly restore drill

- Target RTO: 4 hours; target RPO: 15 minutes. These are operational targets, not provider guarantees.
- Select a recent PITR point and restore to a disposable scratch Supabase project: **requires provider console**.
- Run `supabase link --project-ref "$SCRATCH_PROJECT_REF"` and `supabase db dump --linked --schema public -f /tmp/communityhub-drill.sql`.
- Verify RLS coverage, public/private reads, `payment_transactions`/`payment_events` integrity, deletion queue, storage bucket configuration, and a read-only web smoke test.
- Record start/end time, restore point, achieved RTO/RPO, failed checks, owner, and corrective actions.
- Delete the scratch project and revoke temporary access after evidence is retained.
