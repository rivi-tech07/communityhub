# Refund runbook

| Field                           | Procedure                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Symptom                         | A customer or operator requests a full or partial refund, or a provider refund and `payment_transactions` disagree.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Impact                          | Customer funds, order state, promotion entitlement, and financial reporting may be wrong.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Detection                       | Compare the provider payment ID with `payment_transactions.provider_payment_id`; inspect `status`, `refund_amount_minor`, and `payment_events`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Immediate mitigation            | Do not retry blindly. Set `PAYMENTS_LIVE_ENABLED=false` for an incident, preserve provider IDs, and stop duplicate fulfilment. **requires provider console**                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Root cause investigation        | Confirm provider, currency, amount in minor units, transaction purpose, original payment ID, webhook delivery, and whether a refund already exists. Never edit a successful ledger row to hide a provider action.                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Recovery steps (exact commands) | `curl -X POST "$APP_URL/api/payments/$TRANSACTION_ID/refund" -H "Authorization: Bearer $ADMIN_ACCESS_TOKEN" -H 'content-type: application/json' -d '{"amountMinor":500}'` for a partial refund, or omit `amountMinor` for a full refund. The route requires an administrator session and only accepts `succeeded` transactions. For Stripe, verify or perform the refund using the original PaymentIntent and an idempotency key in the Stripe API/console: **requires provider console**. For Razorpay, verify or perform the refund against the original payment ID: **requires provider console**. Then wait for the signed webhook before treating provider state as final. |
| Post-incident actions           | Confirm `payment_transactions.status` is `partially_refunded` or `refunded`, `refund_amount_minor` is correct, the order/promotion was updated, and support has the provider refund ID. Record the idempotency key and do not expose payment secrets.                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Owner                           | Payments and finance on-call; administrator approval required.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |

Amounts are integer minor units (`pence` for GBP, `paise` for INR). The current admin route does not accept a caller-supplied provider idempotency key, so do not repeat a timed-out request until the provider console/API confirms whether the first refund exists.
